How Claude Code builds, checks, and fixes its own work

The secret is not a smarter model. It is a check Claude can run that says pass or fail, plus a rule that stops Claude from finishing until the check passes. The human writes what the feature should do. Claude plans, builds, tests, fixes, and opens a PR.

"Give Claude a way to verify its work. If Claude has that feedback loop, it will 2–3x the quality of the final result."Boris Cherny, creator of Claude Code (his estimate, not a benchmark)

A Stop hook or /goal keeps Claude inside this loop. Claude cannot finish until the Verify step passes.

The six parts of the setup

Check · most important

A pass/fail check

Tests, typecheck, lint, or build exit code. Put the exact commands in CLAUDE.md. Ask Claude to show the command and its output as evidence.

Check

Test the real app

Unit tests are not enough. Claude starts the app and clicks through it with the Chrome extension or Playwright (browser automation). /run-skill-generator saves how to start your app as a skill.

Gate

Do not stop until it passes

/goal all tests pass and lint is clean, or stop after 20 turns. Or a Stop hook (a script that runs when Claude tries to finish) that blocks while tests fail.

Second opinion

A separate reviewer

Agents rate their own work too kindly. Add a verify-app subagent and a reviewer subagent in .claude/agents/, or run /code-review. Tell it to report real bugs only.

Speed

No permission prompts

Auto mode (a safety classifier approves routine actions): claude --permission-mode auto. Add /sandbox to limit file and network access.

Scale

Many sessions at once

Boris runs 5 local sessions in separate git worktrees plus 5–10 web sessions. /loop fixes failed CI and review comments. Routines run jobs on a schedule or GitHub event.

Start here: a setup you can copy

  1. Write a short CLAUDE.md with your test, lint, and typecheck commands. Add a rule each time Claude makes a mistake.
  2. Add a PostToolUse hook on Edit|Write that runs your formatter.
  3. Run /run-skill-generator so Claude can start and use your app.
  4. Add two subagents: verify-app (end-to-end test steps) and a reviewer.
  5. Turn on auto mode and /sandbox.
  6. For each feature: ask Claude to interview you and write SPEC.md with acceptance criteria. Then, in a fresh session, run /goal <criteria> verified, tests pass.
  7. You review the evidence and the PR. Nothing else.

Watch out

  • No check, no loop. Without a real test, Claude "passes" by saying it is done.
  • Always set a limit (max turns or iterations). Loops can run for hours.
  • Cost grows fast. Anthropic's 3-agent app harness took 6 h and $200, against 20 min and $9 for one agent. The result was much better.
  • A reviewer can over-push. If it reports style nits, Claude adds code it does not need.
  • Boris does not skip permissions. He uses auto mode and pre-approved safe commands.
